接入须知

把这套系统接进其它产品或设计工具之前，先读这一段。左边是不可改的约束，右边是不属于本规范、不要一并带走的东西。

不可改的约束

  • 四档字重必须是四个不同值（400 / 500 / 600 / 700）。合并任意两档会让整页三分之二的文字落在同一个字重上，中文在这个密度下会糊成一块。
  • 正文行高 1.75。中文专用值，不可按拉丁排版惯例压到 1.5。
  • 卡内四档字号 17 / 15 / 13 / 13px。比同版式的拉丁值高约 1.5px —— 同样字号中文要小一号才看得清。
  • 颜色只能从语义别名引用，组件永不直接引色阶。
  • 标题字体栈的顺序不能反 —— Funnel Display 在前、系统黑体在后。反过来中文正常，但拉丁部分会失去展示体。见第 07 节。
  • 不透明度阶梯只用于蒙版与细线，任何情况下不用于文字。

不属于本规范

  • 没有「区块配色方案」这一层。页面靠语义色令牌直接取色，不存在 scheme 抽象，不要为它生成一套。
  • --color-ref-* 是独立体系。它是工具列表页专用的一组颜色，与品牌色板并行存在，两组不能互相推导，也不能合并成一条色阶。
  • 不要生成深色主题。本站是浅色单主题，见第 11 节。
  • #b94d2f 不是品牌色。它是珊瑚 #f2673f 为满足对比度而压深的派生值，只用于承载文字的场合。
  • 色板是品牌标准色，icon 是它的渐变表现。主色 #003a89、punch #e63946、steel #457b9d 以令牌为准；不要从 icon 的渐变里吸色当品牌色用。
  • --color-error 指向 punch-dark，不是基色。白字压 punch 基色只有 4.17:1，过不了 AA。

01品牌资产

logo、favicon、照片。下面所有尺寸和留白都是从线上实测的，不是凭感觉定的。

色板是品牌标准色的权威来源，icon 用渐变来表现它。字标文字固定为主色 #003a89；叶片是左蓝右红的多层渐变，渐变里的每一个色值都只属于 icon，不进色板。需要品牌蓝、品牌红的地方取令牌，不要从 icon 吸色。

标准色与 icon 的关系

icon 的蓝色渐变落在 #04347f–#073a8a 之间，与主色几乎重合；红色渐变落在 #e9232d–#ff432e 之间，比 #e63946 更饱和，只在 icon 内部使用。这三支各自在色板里展开成完整色阶（见第 04 节），构造比例与其余色阶一致。#457b9d / #e63946 / #a8dadc 本就是一套成组的配色，色板里的 --color-aqua-island 即 #a8dadc。

一处必须遵守的派生规则：白字压 punch 基色 #e63946 只有 4.17:1，过不了 AA。 因此语义别名 --color-error 指向 punch-dark #b72d38（6.09:1），基色本身只用于图形填充，不承载白字。

第三方标不在这里

YouTube、哔哩哔哩、Shopify 等标是别家公司的商标，不放进 MIT 许可的公开仓库，留在站点的 src/media/brand/。但站上用它们时有两条规则值得记：

① 一排并列的品牌图标要统一高度，不是统一宽高。YouTube 官方标是 800×524 的横牌，锁进正方形会渲染成 24×15.7px，比旁边 24×24 的方标矮一截。

② 非方形的品牌标自己拼一个方块。站上导航下拉里的 YouTube 图标是「品牌红 #ff0033 实底 + 白色播放三角」，不是原始文件 —— 这样三个平台的图标才是同一个轮廓。

02中文排版三条铁律

本系统服务中文界面，下面三条是不可协商的排版约束。任何一次「让它更紧凑一点」的改动都必须先过这三条。

行高是字号的一部分

类型标尺里每一档都自带行高：正文 1.75，标题 1.3–1.4。不要用 leading-snug / leading-tight 覆盖正文字号——那是拉丁字母的值。同样一个字框里，中文字的笔画密度是字母的好几倍，行距一压，行与行之间的空隙就没了，整段灰成一块。紧行距只给两行以内的卡片标题用。

墨要实

正文和次级文字取颜色令牌，绝不用白/墨加透明度（text-white-60 之类）。透明度会等比削薄每一笔，拉丁字母扛得住，中文扛不住。深色底上用 --color-content-inverse-light。透明度阶梯是给蒙版、导轨、细线用的，不给文字。

AA 是地板，不是及格线

每个文字颜色要在 两个底 上都过 4.5:1——--color-surface（#ffffff）和 --color-surface-alt（#f6fbfb）。只量白底不够 —— 一个在白底上达标的颜色，压到 surface-alt 上会掉到 4.5 以下。而且过了比例也不等于可读：上面两条描述的正是「过了 AA 却读不了」的情况。拿不准就去量渲染出来的页面，别在脑子里推。

推论：--text-tiny 在手机上是 0.625rem（10px）。那是徽章或说明文字的尺寸，永远不能拿来做需要读者去操作的标签。

双语标题的分工是这套排版的核心手法。一个中英混排的标题 ——「20 分钟，快速启动 Shopify 店铺」—— 其中「20」和「Shopify」由 Funnel Display 承担，中文整体交给系统黑体。 靠的是字体栈顺序加各自的字符覆盖范围，不是手动切分标签：前一个字体没有的字，浏览器自动向后找。

结果是拉丁部分获得一个有性格的展示字体，而中文一个字都没有被动过 —— 中文展示体的可选项本就极少，硬套通常只会更糟。全站字体开销 33KB。
三条接入约束：
① 栈的顺序不能反 —— Funnel Display 必须在系统黑体之前，反过来中文正常但拉丁部分失去展示体。
② 只加载 700 一档 —— 正文走系统字体，不需要其余字重。
③ 必须按 unicode-range 分片 —— 浏览器只下载页面上实际出现的字符所在的切片。

--font-heading 只作用于 h1–h6；按钮、导航、卡片标题走 --font-sans。

主题策略：浅色单主题 + 深色区块

本系统没有深色主题，且不打算有。代码中不存在 prefers-color-scheme、data-theme 或 Tailwind 的 dark: 变体。

但系统中存在深色区块 —— 页脚上方的行动区、部分卡片。它们由一组 inverse 令牌实现。「深色区块」与「深色主题」是两件事：区块是设计者主动放在浅色页面里的一块深色，主题是整页颜色的反转。

令牌指向值用途
--color-surface-inversejacksons-purple-dark#002e6d深色区块底
--color-content-inversewhite#ffffff深色区块标题 · 12.84:1
--color-content-inverse-lightjacksons-purple-lighter#cbd7e7深色区块次级文字 · 8.94:1
--color-outline-inversewhite-20白 20%深色区块细线
为什么次级文字是一个实色而不是白色降透明：白色 60% 压在 #002e6d 上量出来是 5.28:1，过 AA——但中文读不了。一个 14px 的「檀」或「繁」在同样的字框里有十几笔，60% 之后它们不再解析成一个字。这是铁律二在深色区块上的具体落点。

若要新增深色主题，须重新验证三件事：正文行高是否仍够（深底上视觉行距会显得更紧）、每个颜色在新底上的对比度、以及所有 ink-* 阴影在深底上是否还可见（通常不可见，需改用描边）。

16四条容易违反的规则

这四条描述的都是「看起来没问题、实际会出错」的情形。它们比色值更难从代码里读出来，接入本系统时必须一并遵守。

01 · 承载文字的颜色，与它的品牌值可以不是同一个

品牌珊瑚 #f2673f 配白字只有 3.09:1，品牌红 #e63946 配白字只有 4.17:1，都过不了 AA。 因此凡是承载文字的场合，它们各自降到深一档：#b94d2f（5.04:1）与 #b72d38（6.09:1）。

这些深色值不是品牌色，是为满足对比度而派生的。品牌基色本身只用于图形填充，不可更改。反过来说， 想让品牌基色出现在按钮上，办法是给它配深色文字而不是白色文字 —— 珊瑚配 #231c1b 是 5.42:1。

02 · 语义别名要成套建立

六条色阶的七档都应有对应的语义别名，而不是用到哪档补哪档。零散补出来的别名会散落在文件各处， 也容易在清理未引用代码时被误删。

03 · 「重」是亮度问题，不是色相问题

一个色块压在浅底上有多沉，等于它的相对亮度。主色 #003a89 的相对亮度是 0.048， 浅底 #f1f4f5 是 0.900 —— 差了近 20 倍。

当反馈是「太重」时，先量亮度再决定换色相还是换明度。从色板里挑一个「感觉浅一点」的色号通常只能挪 0.03， 远不足以改变观感。底色一类的决定应当先定目标亮度，再反推色值。

04 · 字重阶梯必须是四个不同的值

400 / 500 / 600 / 700 四档缺一不可，且用途要分开写明（见第 07 节）。 任意两档合并，整页就会有三分之二的文字节点落在同一个字重上 —— 中文在这个密度下会糊成一块， 拉丁字母则不会。这是本系统与拉丁排版差异最大的一处。

给设计系统工具的说明

如果这份文档是交给自动化工具重建设计系统的，先读这一段。有些东西必须原样保留，有些是历史遗留、不能当成规范。

必须原样保留

  • 四档字重是四个不同值（400/500/600/700）。曾经 bold 与 semibold 同为 600，那是缺陷不是风格。
  • 正文行高 1.75。中文专用值，不要按拉丁排版惯例压到 1.5。
  • 卡内四档字号（17/15/13/13px）。已在拉丁参考值上加过 1.5px，不要退回。
  • 颜色只能从语义别名引用，组件永不直接引色阶。
  • 标题字体是「Funnel Display 在前、HarmonyOS Sans SC 在后」的双语分工，顺序不能反，见第 06 节。
  • 不透明度阶梯只用于蒙版与细线，任何情况下不用于文字。

不要带走 / 不要推导

  • .scheme-1 到 .scheme-4 是死代码。Relume 模板遗留，全站零使用。不要重建成「区块配色方案」。
  • --color-ref-* 与品牌色不要合并。前者是列表页从外部移植的独立体系，两组不能互相推导，也不能统一成一条色阶。
  • 不要生成深色主题。本站是浅色单主题，见第 10 节。
  • #b94d2f 不是品牌色。它是 AA 规则从珊瑚身上压出来的产物，见坑 01。

照片

第三方标不在这里

YouTube、哔哩哔哩、Shopify 等标是别家公司的商标，不放进 MIT 许可的公开仓库，留在站点的 src/media/brand/。但站上用它们时有两条规则值得记：

① 一排并列的品牌图标要统一高度，不是统一宽高。YouTube 官方标是 800×524 的横牌，锁进正方形会渲染成 24×15.7px，比旁边 24×24 的方标矮一截。

② 非方形的品牌标自己拼一个方块。站上导航下拉里的 YouTube 图标是「品牌红 #ff0033 实底 + 白色播放三角」，不是原始文件 —— 这样三个平台的图标才是同一个轮廓。

02中文排版三条铁律

这三条是这个项目上用错误换来的，不是通用建议。它们约束的是所有后续改动——任何一次「让它更紧凑一点」的尝试，都要先过这三条。

行高是字号的一部分

类型标尺里每一档都自带行高：正文 1.75，标题 1.3–1.4。不要用 leading-snug / leading-tight 覆盖正文字号——那是拉丁字母的值。同样一个字框里，中文字的笔画密度是字母的好几倍，行距一压，行与行之间的空隙就没了，整段灰成一块。紧行距只给两行以内的卡片标题用。

墨要实

正文和次级文字取颜色令牌，绝不用白/墨加透明度（text-white-60 之类）。透明度会等比削薄每一笔，拉丁字母扛得住，中文扛不住。深色底上用 --color-content-inverse-light。透明度阶梯是给蒙版、导轨、细线用的，不给文字。

AA 是地板，不是及格线

每个文字颜色要在 两个底 上都过 4.5:1——--color-surface（#ffffff）和 --color-surface-alt（#f6fbfb）。只量白底，是当初正文链接色以 4.45:1 上线到半个站的原因。而且过了比例也不等于可读：上面两条描述的正是「过了 AA 却读不了」的情况。拿不准就去量渲染出来的页面，别在脑子里推。

推论：--text-tiny 在手机上是 0.625rem（10px）。那是徽章或说明文字的尺寸，永远不能拿来做需要读者去操作的标签。

双语标题的分工，是这套排版的核心手法。一个中英混排的标题——「20 分钟，快速启动 Shopify 店铺」——其中「20」和「Shopify」由 Funnel Display 这个展示体承担，中文整体交给 HarmonyOS。靠的不是手动切分标签，而是字体栈顺序加各自的字符覆盖范围：前一个字体没有的字，浏览器自动向后找。

结果是拉丁部分获得了一个有性格的展示字体，而一个中文字都没有被动过——中文展示体的可选项本来就极少，硬套通常只会更糟。代价是 31KB。
迁移时三条不能丢：
① 顺序不能反——Funnel Display 必须在 HarmonyOS 前面，反过来中文会正常但拉丁部分失去展示体。
② 只加载 700——把 400/500 也加载进来，体积翻几倍，而正文根本不用它。
③ 必须分片——不分片就是单文件 2.2MB，首屏会被字体拖死。

另：--font-heading 只作用于 h1–h6（在 global.css 的 base 层），按钮、导航、卡片标题走的都是 --font-sans。

11焦点态与主题策略

这一节是全套文档里唯一包含「建议」而非「现状」的部分。焦点态是这个设计系统当前最大的缺口，主题策略则是一个必须写明、否则会被误解的有意决定。

现状：焦点态几乎不存在

全站只有三处定义了可见焦点：

另一个问题：现有焦点环的颜色在两个底上不达标

焦点环属于图形元素，阈值是 3:1（不是文字的 4.5:1）。现用的 --color-secondary #f2673f 实测：

主题策略：浅色单主题 + 深色区块

本站没有深色模式，这是有意的决定，不是待办事项。代码里没有 prefers-color-scheme，也没有 data-theme 或 Tailwind 的 dark: 变体。

但站上确实存在深色区块——页脚上方的 CTA、部分卡片。它们靠一组 inverse 令牌实现，这是「深色区块」而不是「深色主题」，两者的区别在于：区块是设计者主动选择放在浅色页面里的一块深色，主题是整页颜色的反转。

令牌指向值用途
--color-surface-inversejacksons-purple-dark#242c68深色区块底
--color-content-inversewhite#ffffff深色区块标题 · 12.84:1
--color-content-inverse-lightjacksons-purple-lighter#d4d6e6深色区块次级文字 · 8.90:1
--color-outline-inversewhite-20白 20%深色区块细线
为什么次级文字是一个实色而不是白色降透明：白色 60% 压在 #242c68 上量出来是 5.28:1，过 AA——但中文读不了。一个 14px 的「檀」或「繁」在同样的字框里有十几笔，60% 之后它们不再解析成一个字。这是铁律二在深色区块上的具体落点。

如果未来真要做深色主题，需要重新验证的不是颜色数量而是这三件事：正文行高是否仍够（深底上视觉行距会显得更紧）、每个颜色在新底上的比值、以及所有 ink-* 阴影在深底上是否还可见（大概率不可见，需要换成描边）。

16四个坑

这四条比色值更值得带走——它们是这套系统里最容易被重新踩一遍的地方。

01 · AA 规则会自己生出一个新颜色

品牌珊瑚 #f2673f 配白字只有 3.09:1。系统为了让它过 AA，自动把承载文字的 flamingo 一律压深到 #b94d2f——那是一个棕色，从来没有人挑过它，它是「珊瑚 + 白字」这个组合逼出来的。
解法：改配色而不是改色号。珊瑚配深墨字 5.42:1，珊瑚就能以原色出现。

02 · 语义别名要成套定义

--color-secondary-lightest / -darker 这类别名在初版中不存在，用到时才发现缺失。迁移时把六条色阶的七档全部建立对应的语义别名，而不是用到哪档补哪档——补出来的会散落在各处，也容易在「清理死代码」时被误删（本项目就发生过两次）。

03 · 「重」是亮度问题，不是色相问题

一个色块压在浅底上有多沉，等于它的相对亮度。深海军蓝 #2d3782 的相对亮度是 0.049，浅底 #f1f4f5 是 0.900——差了近 20 倍。当反馈是「太重」时，先量亮度再决定换色相还是换明度，从色板里挑「感觉浅一点」的色号通常只能挪 0.03。

04 · 字重阶梯要真的是阶梯

bold 与 semibold 同为 600 时，整套系统失去粗体这一档，页面上三分之二的文字节点会落在同一个字重上。中文在这个密度下会糊成一块。四档字重必须是四个不同的值，且用途要分开写明（见第 06 节）。
